# 台大女八舍宿網 Line Chatbot 對話/功能設計

## 主題

**台大女八舍宿網小精靈** - 專門協助學生解決宿舍網路相關問題的智慧問答機器人。

- **定位**：協助學生解決宿舍網路相關問題
- **目標使用者**：台大女八舍住宿學生
- **核心價值**：提供 24/7 自動化網路問題診斷與解決方案

## 功能列表

### 主要功能（主選單）

1. **🚫 無法上網** - 連線故障排除
   - 多人同時遇到問題的排查流程
   - 個人問題的診斷與解決方案
   - 路由器設定檢查
   - 硬體與設定問題排查

2. **📝 如何註冊** - 宿網註冊教學
   - 第一次註冊完整流程
   - 使用路由器註冊教學
   - MAC 地址設定與修改
   - 註冊疑難排解

3. **🐢 網速很慢** - 網速與流量查詢
   - 流量使用查詢
   - 測速檢測工具
   - 網速問題分析

4. **📞 聯絡網管** - 聯絡資訊與報修流程
   - 網管聯絡方式
   - 報修流程說明
   - 需要準備的資訊清單

5. **🔍 查詢違規狀態** - 帳號/資安層問題
   - 查詢是否被封鎖
   - 違規主機名單查詢
   - MAC 地址問題排查

### Rich Menu（圖文選單）

提供常駐選單，讓使用者隨時可以從主選單選擇功能，無需輸入文字。

## 對話腳本

### 使用的 LINE Reply Templates

#### 1. Text Message（純文字訊息）
- **使用時機**：簡單說明、提示訊息、Gemini AI 回應
- **範例**：歡迎訊息、錯誤提示、簡單說明
- **實作**：`createTextMessage()` 函數

#### 2. Quick Reply（快速回覆）
- **使用時機**：需要使用者快速選擇選項、引導下一步
- **範例**：
  - 主選單的「回主選單」選項
  - 問題分類選項（多人問題/個人問題）
  - 後續操作選項
- **實作**：`createQuickReply()` 函數

#### 3. Button Template（按鈕模板）
- **使用時機**：主選單、功能分類、選項選擇
- **範例**：
  - 主選單（4 個主要功能按鈕）
  - 註冊類型選擇
  - 路由器 FAQ
- **實作**：`createButtonTemplate()` 函數

#### 4. Carousel Template（輪播模板）
- **使用時機**：多個相關選項、分類說明、步驟清單
- **範例**：
  - 註冊前置準備檢查清單
  - 症狀診斷選項（硬體/設定/封鎖）
  - 路由器設定方法選擇
- **實作**：`createCarouselTemplate()` 函數

#### 5. Flex Message（彈性訊息）
- **使用時機**：需要豐富格式、長篇內容、結構化資訊
- **範例**：
  - 路由器故障排除步驟（支援粗體文字）
  - 硬體檢查流程（結構化內容）
  - 註冊前置準備（詳細檢查清單）
  - 網域不在女八舍問題（包含 Email 資訊）
  - 帳號/資安層問題（包含查詢連結）
- **實作**：`createFlexMessage()` 函數

#### 6. URI Action（外部連結）
- **使用時機**：開啟外部網站、查詢工具、教學文件
- **範例**：
  - 流量查詢連結
  - 測速網站連結
  - 註冊網站連結
  - 查詢違規主機名單連結
- **實作**：`createButtonWithUri()` 函數

#### 7. Postback Action（回傳資料）
- **使用時機**：觸發特定流程、狀態切換、選項選擇
- **範例**：
  - 主選單功能選擇（`action:connection_troubleshoot`）
  - 問題分類（`network:step1:single`）
  - 流程控制（`menu` 回主選單）
- **實作**：`createButtonWithPostback()` 函數

#### 8. In-app Browser（應用程式內瀏覽器）
- **使用時機**：外部教學文件、詳細說明頁面
- **範例**：
  - IP/DNS 設定教學 PDF
  - 註冊步驟教學 PDF
- **實作**：`createButtonWithUri()` 搭配 `altUri` 設定

### 對話流程設計

#### 主要對話流程

```
主選單
  ├─ 🚫 無法上網
  │   ├─ 多人問題 → 路由器檢查 → 流量檢查 → 報修流程
  │   └─ 個人問題 → 連接方式判定
  │       ├─ 路由器 → 路由器故障排除
  │       └─ 電腦直連 → 症狀診斷
  │           ├─ 硬體問題
  │           ├─ 設定問題
  │           └─ 封鎖問題
  │
  ├─ 📝 如何註冊
  │   ├─ 第一次註冊 → 前置準備 → 註冊步驟
  │   ├─ 使用路由器 → 路由器設定 → MAC 地址設定
  │   ├─ 修改 MAC 地址 → 更換電腦 / MAC 重複
  │   └─ 疑難排解 → 無法進入 / 資料問題 / 其他
  │
  ├─ 🐢 網速很慢
  │   ├─ 流量查詢 → 查詢連結 / 流量限制說明
  │   └─ 測速檢測 → 校內測速 / 校外測速 / 結果分析
  │
  └─ 📞 聯絡網管
      ├─ 聯絡方式 → Email / 報修流程
      └─ 提供資訊清單 → 需要準備的資訊
```

#### 對話節點統計

- **總節點數**：31+ 個對話節點
- **主要分類**：
  - 無法上網：10+ 個節點
  - 如何註冊：12+ 個節點
  - 網速很慢：5+ 個節點
  - 聯絡網管：4+ 個節點

## 對話脈絡：在回覆時維持上下文

### 狀態管理

系統使用 `Conversation` 模型的 `metadata.step` 欄位來追蹤對話狀態：

- **`network:step1`**：詢問問題影響範圍（多人/個人）
- **`network:conn_type`**：詢問連接方式（路由器/電腦直連）
- **`network:router:troubleshoot`**：路由器故障排除流程
- **`network:step2`**：詢問症狀類型（完全無法/斷斷續續）
- **`network:multi:router_check`**：多人問題路由器檢查
- **`network:multi:check_traffic`**：多人問題流量檢查

### 上下文維持

- **對話歷史**：保留最近 10 則訊息作為上下文，傳入 `processUserMessage()` 函數
- **分類追蹤**：使用 `category` 欄位追蹤當前問題分類（`network_issue`, `registration`, `speed_check`, `contact`）
- **狀態清除**：當使用者選擇「回主選單」時，清除所有對話狀態（`metadata: {}`, `category: undefined`）

### 意圖分類與路由

系統使用 Gemini API 進行意圖分類，判斷使用者訊息類型：

- **`menu`**：明確要求回主選單
- **`connection_troubleshoot`**：無法上網或連線問題
- **`registration`**：註冊相關問題
- **`speed_check`**：網速或流量問題
- **`contact`**：聯絡網管
- **`continue_flow`**：繼續當前流程的回答
- **`new_question`**：在流程中提出新問題（Context Switching）
- **`information_query`**：詢問資訊（一般性查詢，使用 RAG）
- **`greeting`**：打招呼或感謝
- **`unrelated`**：完全無關的問題

### Context Switching（上下文切換）

當使用者在流程中提出新問題時：
1. 系統暫存當前對話狀態
2. 使用 Gemini 回答新問題（結合知識庫 RAG）
3. 回答完後提醒使用者可以返回原流程
4. 使用者可以選擇繼續原流程或開始新對話

### 關鍵字匹配（降級方案）

當 Gemini API 無法使用時，系統降級到關鍵字匹配：

- **核心功能關鍵字**：無法上網、如何註冊、網速很慢、聯絡網管
- **問題分類關鍵字**：多人、個人、路由器、直接連線
- **症狀關鍵字**：完全無法、斷斷續續、網速慢
- **特殊指令**：選單、回主選單、重新開始

```
你的回答應該：

2. 提供具體的解決步驟
3. 必要時引導學生提供更多資訊
4. 使用繁體中文回答
5. 能夠理解使用者的自由文字回應，即使不是標準選項
6. 根據使用者提供的資訊，給出下一步的指引
7. 回覆中不要用任何markdown語法，只要純文字回覆
```

### 知識庫（Knowledge Base）

包含常見問題與解決方案，定義在 `lib/gemini/prompts.ts` 中的 `KNOWLEDGE_BASE`：

- **網路連線問題**：多人/個人問題的排查方法
- **資安事件**：掃毒流程、處理步驟
- **註冊問題**：註冊網站、MAC 地址設定、路由器配置
- **回信範本**：標準回應格式

### Prompt 建構邏輯

`buildPrompt()` 函數會根據以下資訊建構完整的 Prompt：

1. **系統提示**：定義 AI 的角色與回答風格
2. **問題分類**：根據當前對話分類提供更詳細的指引
3. **知識庫**：提供相關的技術知識與解決方案
4. **對話上下文**：包含最近 10 則訊息，維持對話連貫性
5. **使用者訊息**：當前使用者的問題或回應

## 回應設計：根據預設腳本 and/or LLM 回覆，包裝成適當的回應

### 回應優先順序

1. **特殊指令處理**：選單、回主選單等指令（快速路徑，不呼叫 Gemini）
2. **快速匹配**：特定關鍵字（如「查詢違規狀態」）直接返回對應節點
3. **意圖分類**：使用 Gemini 進行意圖分類（主要判斷邏輯）
4. **固定腳本**：明確功能（無法上網、註冊等）走固定節點（`conversation-nodes.ts`）
5. **LLM 生成**：資訊查詢、新問題等由 Gemini 生成回答（結合 RAG）
6. **降級方案**：預設腳本回應或錯誤提示

### 回應格式選擇

根據內容長度與複雜度選擇適當的訊息格式：

- **短文字**：Text Message 或 Quick Reply
- **選項選擇**：Button Template 或 Carousel Template
- **長篇內容**：Flex Message（支援粗體、結構化內容）
- **外部連結**：URI Action 或 In-app Browser

### 固定腳本 vs LLM 回應

#### 固定腳本（`conversation-nodes.ts`）

用於：
- 主選單、功能選擇
- 明確的流程步驟（如註冊步驟、故障排除步驟）
- 結構化的選項（如問題分類、症狀診斷）

優點：
- 回應速度快
- 格式一致
- 可預測

#### LLM 回應（Gemini API）

用於：
- 資訊查詢（結合 RAG）
- 新問題回答（Context Switching）
- 非標準輸入的理解與轉換
- 打招呼、無關訊息的處理

優點：
- 靈活理解使用者意圖
- 結合知識庫提供詳細回答
- 支援自然語言對話

### 混合模式

系統採用混合模式，根據意圖分類決定使用固定腳本或 LLM：

- **`connection_troubleshoot`** → 固定腳本（`createConnectionTroubleshootNode()`）
- **`registration`** → 固定腳本（`createRegistrationTypeSelectionNode()`）
- **`speed_check`** → 固定腳本（`createSpeedCheckNode()`）
- **`contact`** → 固定腳本（`createContactNode()`）
- **`information_query`** → LLM + RAG（`searchKnowledgeSources()` + `buildKnowledgeContext()`）
- **`new_question`** → LLM + Context Switching
- **`continue_flow`** → LLM 理解後轉換為標準答案，再由固定腳本處理

### 錯誤處理

- **LLM 配額錯誤（429）**：顯示友善提示，引導使用選單
- **模型不存在錯誤（404）**：降級到備用模型（gemini-pro, gemini-1.0-pro），再降級到關鍵字匹配
- **無關訊息**：溫柔引導，說明能力範圍，提供功能入口
- **打招呼**：友善回應，引導到主選單
- **無法理解**：顯示友善的錯誤訊息，提供回主選單選項

### 使用者體驗優化

- **每個節點都有「回主選單」選項**：讓使用者隨時可以重新開始
- **漸進式資訊提供**：先給概覽，再提供詳細步驟
- **多種呈現方式**：Text 說明 + In-app Browser 詳細文件
- **交叉連結**：相關節點之間可以互相連結
- **去重機制**：防止 LINE 重送事件導致重複回應

## 技術實作細節

### 訊息處理流程

1. **接收訊息**：LINE Webhook 接收使用者訊息（`app/api/line/webhook/route.ts`）
2. **驗證簽章**：使用 HMAC-SHA256 驗證 LINE 訊息簽章
3. **去重檢測**：檢查 `webhookEventId` 是否已處理過
4. **判斷類型**：Postback 事件 / 文字訊息 / Follow 事件
5. **處理訊息**：根據類型與對話狀態處理（`lib/bottender/handlers.ts`）
6. **產生回應**：使用固定腳本或 Gemini AI（`lib/services/message.ts`）
7. **儲存記錄**：將對話儲存到 MongoDB（`lib/db/models/`）
8. **回傳回應**：透過 LINE Messaging API 回傳（Reply API，失敗時使用 Push API）

### 對話狀態管理

- **狀態設定**：當進入特定對話流程時，設定 `metadata.step`（如 `network:step1`）
- **狀態檢查**：處理使用者訊息時，先檢查當前對話狀態（`conversationStep`）
- **狀態清除**：完成對話流程或選擇「回主選單」時清除狀態（`metadata: {}`）

### 降級機制

1. **Gemini 分類器失敗**：降級到關鍵字匹配
2. **關鍵字匹配失敗**：使用 Gemini 理解並回應（如果可用）
3. **Gemini 回應失敗**：降級到預設腳本
4. **所有方法失敗**：顯示錯誤提示並引導到主選單

### 效能優化

- **Profiling Logs**：webhook 中有詳細的效能日誌（T0-T10, H0-H9）
- **快速路徑**：特殊指令（如「選單」）直接返回，不呼叫 Gemini
- **去重機制**：防止重複處理相同事件
- **Reply API 優先**：使用 Reply API，失敗時才使用 Push API

## 功能特色

1. **智慧分類**：使用 Gemini API 進行意圖分類，提供適當回應
2. **溫柔引導**：對於無關訊息，禮貌地說明能力範圍並提供功能入口
3. **狀態追蹤**：維持對話脈絡，提供連貫的對話體驗
4. **多種訊息格式**：根據內容選擇最適合的 LINE 訊息格式
5. **完整對話記錄**：所有對話都儲存到資料庫，方便後續分析
6. **RAG 整合**：結合知識庫提供詳細、準確的回答
7. **Context Switching**：支援流程中跳轉，回答新問題後可返回原流程
8. **錯誤降級**：多層降級機制，確保系統穩定運作
